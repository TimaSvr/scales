# Руководство разработчика экранных форм и этикеток Scales Client

Данный документ предназначен для программистов и описывает процесс создания и редактирования пользовательского интерфейса (экранных форм) и шаблонов печати (этикеток) для терминалов Scales Client.

## 1. Разработка экранных форм (RFW)

Пользовательский интерфейс терминала описывается с помощью технологии Remote Flutter Widgets (RFW). Экранные формы хранятся в виде текстовых файлов с расширением .rfwtxt.

Файл экранной формы имеет декларативную структуру и состоит из нескольких обязательных элементов. В начале файла располагаются директивы импорта, подключающие базовые библиотеки и библиотеку кастомных виджетов: import core;, import material; и import custom;. Далее следует виджет конфигурации с именем config, который служит для передачи настроек из экранной формы в Dart-код. Через него задаются цвета, размеры шрифтов, списки поддерживаемых языков и другие параметры отображения. Замыкает структуру корневой виджет с именем root, являющийся точкой входа для отрисовки интерфейса, внутри которого описывается вся иерархия элементов экрана.

Взаимодействие экранной формы с бизнес-логикой приложения осуществляется через два механизма. Для вывода динамической информации используются обращения к источнику данных через префикс data, например data.selectedGood.name или data.goods. Для обработки действий пользователя используется конструкция event, которая передает идентификаторы или другие параметры в Dart-код при нажатии на элементы.

При разработке необходимо учитывать, что парсер RFW не является полноценным языком Dart. В нем запрещена конкатенация строк через знак плюс, оператор null-coalescing (два знака вопроса) и оператор безопасной навигации (вопросительный знак с точкой). Арифметические операции внутри выражений также не поддерживаются. Для условий используются конструкции switch и тернарный оператор, а для итераций — цикл for ... in.

### 1.1. Механизм горячей замены экранов (Hot Swap)

Одной из ключевых особенностей использования технологии RFW в проекте является возможность изменения пользовательского интерфейса без перекомпиляции и перезапуска самого приложения. Разработчик вносит изменения в текстовый файл .rfwtxt и загружает его в систему (через сервер или локальный импорт). Приложение считывает новый код экрана, парсит его и перерисовывает интерфейс на лету. Для предотвращения сбоев перед применением нового шаблона функция verifyRfwText проверяет его валидность. Если в файле обнаружена ошибка, новый экран не применяется, терминал продолжает использовать ранее загруженную версию, а текст ошибки с указанием строки и символа записывается в лог.

## 2. Источники данных, конфигурация и события

Для успешной разработки интерфейса необходимо понимать, какие данные приходят из Dart-кода в экранную форму, какие настройки передаются обратно и какие события генерируются при взаимодействии пользователя с экраном. Вся логика обработки данных и событий сосредоточена в файле lib/ui/rfw/remote.dart (класс _RemotePanelState).

### 2.1. Поля данных (data)

В экранную форму передается объект DynamicContent, который обновляется через методы _previewData.update() и _previewData.updateAll(). Начальные значения задаются в словаре _defaultData. Экранная форма обращается к этим данным через префикс data..

Поле useScreen (строка) определяет текущий режим отображения экрана. Может принимать значения main (главный экран с группами товаров), search (экран поиска), list (список товаров группы) или good (карточка выбранного товара). В зависимости от этого значения виджет root в экранной форме подставляет нужный контейнер.

Поле selectedColumns (целое) задает максимальное количество последних выбранных товаров, отображаемых на главном экране. Поле showZero и showTare (логические) управляют отображением кнопок установки нуля и тары. Поле sectionColumns и sectionRows (целые) задают количество колонок и строк в таблице групп товаров. Поле sections (список) содержит массив объектов групп товаров для отображения.

Поле goodColumns и goodRows (целые) задают размеры сетки для таблицы


ров. Поле goods (список) содержит массив объектов товаров. Поле selectedGoods (список) содержит массив последних выбранных товаров. Поле selectedGood (объект) содержит данные конкретного товара, открытого в карточке.

Поле moreItems (логическое) указывает, есть ли еще страницы для пролистывания. Поле page и totalPages (строки) содержат текущий номер страницы и общее количество страниц. Поле printerStatus (логическое) указывает на готовность принтера. Поле printerAlertMessage (строка) содержит текст ошибки принтера. Поле scripts (словарь) содержит текстовые надписи для текущего языка интерфейса (например, заголовки полей в карточке товара).

### 2.2. Поля конфигурации (config)

Виджет config (класс ScalesConfig в Dart) позволяет передать из экранной формы в приложение глобальные настройки отображения. Эти настройки сохраняются в словарь AppCache.remoteConfig и используются для построения интерфейса. Конфигурация считывается один раз при загрузке экрана.

Параметр selectedCols задает максимальное количество отображаемых последних товаров. Параметры goodCols и goodRows задают количество колонок и строк в таблице товаров, а foundGoodCols и foundGoodRows — в таблице результатов поиска. Параметр sectionRows задает количество строк в таблице групп товаров.

Цветовые параметры mpBackColor, mpTextColor, mpValueTextColor и mpUnfixedWeightColor задают цвет фона и текста для панели индикации. Параметры alertColor и warningColor задают цвета для сообщений об ошибках и предупреждений. Флаг mpHidePrinterErrors позволяет скрыть некоторые ошибки принтера (например, отсутствие бумаги).

Параметры сортировки goodSortOrder (направление: asc или desc) и goodSortField (поле: name, code, hotkey, shortcode) определяют порядок вывода товаров. Параметр goodSearchCode указывает, по какому полю выполняется поиск. Список languages содержит перечень поддерживаемых языков с кодами, названиями и наборами текстовых скриптов для перевода интерфейса.

### 2.3. События (event)

Когда пользователь взаимодействует с интерфейсом, экранная форма генерирует событие, которое передается в Dart-код. Обработка событий происходит в методе onEvent класса RemotePanel. События объявляются в экранной форме с помощью конструкции event.

Событие onSectionTap передает идентификатор нажатой группы товаров (id). Вызывается при нажатии на ячейку группы в каталоге. В Dart-коде вызывает переход в выбранную группу и загрузку ее содержимого.

Событие onGoodTap передает идентификатор товара (id). Вызывается при нажатии на карточку товара. В Dart-коде открывает карточку товара, а при включенной авто-печати может инициировать печать этикетки.

Событие onHomeButton вызывается при нажатии на кнопку «Домик» и выполняет сброс состояния к главному экрану.

События onPageUpButton и onPageDownButton вызываются при нажатии на кнопки пролистывания страниц и меняют текущее смещение выборки.

Событие onTreeUpButton вызывается для перехода на уровень выше в иерархии групп товаров.

Событие onCloseGood передает идентификатор товара (id) и вызывается при закрытии карточки товара. В Dart-коде добавляет товар в список последних выбранных и возвращает на главный экран.

Событие onPrintGood передает идентификатор товара (id) и вызывается при нажатии на кнопку печати. В Dart-коде инициирует печать этикетки, если весы стабильны.

События onPiecePlus и onPieceMinus передают идентификатор товара (id) и вызываются для изменения количества штучного товара.

Событие searchKeyPressed передает режим поиска (mode) и введенный текст (text). Вызывается при нажатии на клавиши экранной клавиатуры. В Dart-коде выполняет поиск товаров и обновляет список отображаемых результатов.

События onZero, onTare и onFeed вызываются при нажатии на соответствующие кнопки и отправляют команды напрямую в оборудование (установка нуля, установка тары, протяжка ленты).

Событие setLanguage передает код языка (lang) и вызывается для переключения языка интерфейса.

### 2.4. Логика обновления данных (data)

Данные на экране обновляются по мере работы пользователя. Методы _previewData.update() (обновляет одно поле) и _previewData.update


All() (обновляет несколько полей сразу) вызываются в различных ситуациях.

Метод loadData формирует основной набор данных в зависимости от текущего режима. Если открыт главный экран (VIEW_MODE_MAIN), то через update задаются selectedColumns, showZero, showTare и scripts. Если текущая группа содержит подгруппы, через update задается список sections и через updateAll — useScreen (значение main), sectionColumns, sectionRows, moreItems, page, totalPages. Если группа содержит товары, через updateAll задаются useScreen (значение list), goodColumns, goodRows, goods, moreItems, page, totalPages.

При переходе в режим поиска (VIEW_MODE_SEARCH) метод loadData выполняет поиск товаров в базе и через updateAll задает useScreen (значение search), goodColumns, goodRows, goods, moreItems, page, totalPages.

При открытии карточки товара (VIEW_MODE_GOOD) метод displayGood через updateAll задает selectedGood (объект с данными товара) и useScreen (значение good).

При добавлении товара в список последних выбранных метод appendSelectedGood через update обновляет поле selectedGoods.

При изменении статуса принтера метод onDeviceStatus через update обновляет поле printerAlertMessage и, при необходимости, поле printerStatus.

При отображении всплывающего сообщения метод showAlert через update записывает текст в поле alertMessage, а через секунду очищает его.

При смене языка метод setLanguage (если реализован) должен обновлять поле scripts в соответствии с выбранным языком.

## 3. Каталог кастомных элементов

При разработке экранных форм стандартных виджетов Flutter не всегда достаточно для отображения специфических данных терминала, таких как штрих-коды, изображения из локальных папок или специализированные клавиатуры. Для этого в приложении реализована библиотека custom, которая содержит набор дополнительных виджетов на Dart.

В данном разделе приведен справочник уже реализованных кастомных элементов. При создании нового экрана .rfwtxt разработчику следует использовать элементы из этого каталога, чтобы не дублировать уже написанный функционал. Все элементы зарегистрированы в файле lib/utils/appcache.dart (метод createCustomWidgets).

### 3.1. Элементы управления

Виджет JIconButton представляет собой квадратную кнопку с иконкой, вписанной в нее. В качестве параметров принимает код иконки из шрифта Material (iconCode), имя PNG-файла из папки assets/icons (iconName), цвет иконки в формате ARGB (color) и обработчик нажатия (onPressed). Если обработчик не задан, иконка отображается полупрозрачной, имитируя неактивное состояние.

Пример использования:

```text
JIconButton(
  iconCode: 0xe047,
  color: 0xFF00B2CE,
  onPressed: event "onCloseGood" { id : data.selectedGood.id }
)
```

Виджет SearchKeyboard реализует экранную клавиатуру для поиска товаров. Принимает объект style, в котором задаются раскладки клавиатуры (searchLayouts), цвета фона клавиш и текста, цвет поля ввода и его рамки, а также размер шрифта (fontSize). Обработчик события onKeyPress передает в Dart-код текущий режим поиска и введенный текст.

Пример использования:

```text
SearchKeyboard(
  style : {
    searchLayouts: "code,kz,ru",
    keyBackColor: 0xFF00B2CE,
    keyTextColor: 0xFFF1E5AC,
    fontSize: 32.0
  },
  onKeyPress: event "searchKeyPressed" { }
)
```

### 3.2. Отображение изображений и графики

Виджет ImageFile выводит изображение из локального файла. Принимает путь к файлу (path) и режим вписывания (fit), который может быть cover или contain. Если путь начинается с префикса shared:, файл ищется в папке общих ресурсов приложения. При ошибке загрузки отображается стандартная иконка битого изображения.

Пример использования:

```text
ImageFile(path: data.selectedGood.image, fit: "cover")
```

Виджет ImageBase64 выводит изображение, закодированное в строке Base64. Принимает саму строку (data) и режим вписывания (fit). Используется для отображения изображений, полученных с сервера или из базы данных.

Пример использования:

```text
ImageBase64(data: data.selectedGood.image, fit: "contain")
```

Виджет CircleImage выводит изображение, обрезанное по кругу, с настраиваемой


рамкой. Принимает путь к файлу (path), цвет рамки (borderColor) и ее толщину (borderWidth). Вокруг изображения добавляется небольшой внутренний отступ.

Пример использования:

```text
CircleImage(path: data.selectedGood.image, borderColor: 0xFF00B2CE, borderWidth: 4.0)
```

Виджет BarcodeImage выполняет генерацию и вывод штрих-кода товара в формате EAN-13. Принимает объект товара с его полями (good), цвет штрих-кода (color) и вес (weight). Штрих-код генерируется на основе формата, заданного в настройках товара или конфигурации.

Пример использования:

```text
BarcodeImage(good: data.selectedGood, color: 0xFF00B2CE)
```

### 3.3. Контейнеры и компоновка

Виджет Scrollbar добавляет полосу прокрутки для списков и других прокручиваемых областей. Принимает флаг видимости полосы (thumbVisibility) и дочерний виджет (child), который будет прокручиваться.

Пример использования:

```text
Scrollbar(
  thumbVisibility: true,
  child: SingleChildScrollView(child: Text(text: data.selectedGood.brieftext))
)
```

Виджет LayoutGrid реализует сетку для выравнивания элементов. Принимает количество колонок (columnSizes) и строк (rowSizes), расстояния между колонками и строками (columnGap, rowGap), а также список дочерних элементов (children). Используется для построения таблиц товаров и групп.

Пример использования:

```text
LayoutGrid(
  columnSizes: data.goodColumns,
  rowSizes: data.goodRows,
  rowGap: 6.0,
  columnGap: 6.0,
  children: [
    ...for item in data.goods:
      GoodCell(item: item)
  ]
)
```

Виджет StyledCard создает контейнер с закругленными углами, фоном и рамкой. Принимает внутренние отступы (padding), радиус скругления (radius), цвет фона (color), цвет и толщину рамки (borderColor, borderWidth). Используется для визуального выделения карточек товаров.

Пример использования:

```text
StyledCard(
  padding: 4.0,
  radius: 4.0,
  color: 0xFFECF0F1,
  borderColor: 0xFF00B2CE,
  borderWidth: 1.0,
  child: Text(text: args.item.name)
)
```

Виджет BorderBox создает контейнер с рамкой и закругленными углами. Принимает цвет рамки (color), ее толщину (width) и радиус скругления (radius). В отличие от StyledCard, не задает цвет фона.

Пример использования:

```text
BorderBox(color: 0xFF00B2CE, width: 2.0, radius: 8.0, child: Text(text: "Товар"))
```

Виджет ClipRRect обрезает дочерний виджет по скругленным углам. Принимает радиус скругления (borderRadius) и дочерний виджет (child). Используется для придания изображениям и контейнерам скругленной формы.

Пример использования:

```text
ClipRRect(borderRadius: 12.0, child: ImageFile(path: data.selectedGood.image))
```

Виджет ClipOval обрезает дочерний виджет по овалу. Принимает только дочерний виджет (child). В текущей реализации используется редко, так как для круглых изображений есть более специализированный виджет CircleImage.

Пример использования:

```text
ClipOval(child: ImageFile(path: data.selectedGood.image))
```

Виджет DecoratedBox создает контейнер с декоративным фоном и закругленными углами. Принимает цвет фона (decoration.color) и радиус скругления (decoration.borderRadius). Используется для создания цветных подложек под элементы интерфейса.

Пример использования:

```text
DecoratedBox(
  decoration: { color: 0xFF00B2CE, borderRadius: 6.0 },
  child: Text(text: args.item.name)
)
```

### 3.4. Системные контейнеры

Виджет ScalesContainer является корневой оберткой для всего экрана. Принимает дочерний виджет (child). В текущей реализации просто возвращает Container с дочерним виджетом, но в будущем может использоваться для добавления общих элементов, таких как фон или системные панели.

Пример использования:

```text
widget root = ScalesContainer(child: MainPanel());
```

Виджет ScalesConfig является конфигуратором экранной формы. Не отображает никаких элементов, а считывает параметры из RFW и сохраняет их в глобальную переменную AppCache.remoteConfig. Принимает параметры цветов (mpBackColor, mpTextColor, mpValueTextColor, mpUnfixedWeightColor, alertColor, warningColor), размеров сеток (selectedCols, goodCols, goodRows, sectionRows), настроек сортировки (goodSortOrder,


goodSortField), режима поиска (searchMode, goodSearchCode), флага скрытия ошибок принтера (mpHidePrinterErrors) и списка поддерживаемых языков (languages). Каждый язык описывается кодом, названием, коротким названием и набором текстовых скриптов.

Пример использования:

```text
widget config = ScalesConfig(
  selectedCols: 6,
  goodCols: 4,
  goodRows: 3,
  mpBackColor: 0xFF00B2CE,
  mpTextColor: 0xFFFEC104,
  goodSortOrder: "asc",
  goodSortField: "shortcode",
  languages: [
    {
      "code": "ru",
      "name": "Русский",
      "shortName": "РУС",
      "scripts": [
        {"code":"goodCode", "text": "Код товара"}
      ]
    }
  ]
);
```

## 4. Разработка этикеток

Шаблоны этикеток представляют собой файлы в формате SVG (.svg). Файл этикетки должен содержать атрибут data-id="ps_scales_label" в корневом теге \<svg\>. Это необходимо для корректного определения типа файла при импорте и загрузке через сервер.

В SVG-файле используются специальные маркеры (плейсхолдеры), которые при печати заменяются на реальные данные товара. Маркеры вставляются в текстовые элементы SVG и обрабатываются модулем lib/utils/label.dart перед отправкой на принтер.

Маркер #000 обозначает порядковый номер этикетки. Используется для нумерации отпечатанных этикеток в пределах текущей смены.

Пример использования в шаблоне:

```text
<text x="10" y="20">#000</text>
```

Маркер КОД ТОВАРА обозначает код товара.

Пример использования в шаблоне:

```text
<text x="10" y="40">КОД ТОВАРА: 41756</text>
```

Маркер УПАКОВАНО обозначает дату упаковки товара.

Пример использования в шаблоне:

```text
<text x="10" y="60">УПАКОВАНО: 05.09.2026</text>
```

Маркер ГОДЕН ДО обозначает срок годности товара.

Пример использования в шаблоне:

```text
<text x="10" y="80">ГОДЕН ДО: 05.09.2026</text>
```

Маркер ВЕС обозначает текущий вес товара на весах.

```text
<text x="10" y="140">СТОИМОСТЬ: 65.60 ₸</text>
```

Маркер OPERATOR обозначает имя оператора, выполнившего взвешивание.

Маркер TARE обозначает вес тары.

Пример использования в шаблоне:

```text
<text x="10" y="180">ТАРА: 0.000</text>
```

При разработке шаблона рекомендуется использовать стандартные шрифты, поддерживающие кириллицу, чтобы избежать проблем с отображением русских и казахских символов. Проверка шаблона осуществляется на реальном терминале с помощью команды «Печать тестовой этикетки» в сервисном режиме. Если принтер не поддерживает прямой рендеринг SVG, шаблон предварительно конвертируется в растровое изображение силами приложения.
